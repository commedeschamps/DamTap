# DamTap

DamTap — маркетплейс еды по выгодным ценам в Астане. Находите блюда по вкусу,
сохраняйте любимое и помогайте сокращать пищевые отходы.

Интерфейс на русском языке: поиск по блюдам, заведениям, районам и адресам,
категории, сортировка предложений, карточки с деталями самовывоза и избранное. Фирменный знак Fork in D — тёмно-бирюзовая D с белой трёхзубой вилкой и зелёным листом; используется точный предоставленный логотип с надписью DamTap.

## Разработка

Next.js App Router, React, TypeScript, Tailwind CSS v4. Основной шрифт — Manrope.

```bash
npm install
npm run dev
npm run lint
npm test
npm run build
npm start
```

Для сборки используется Webpack. Manrope включён в репозиторий в `public/fonts`; сборка не скачивает шрифты и не требует Google Fonts. Карта загружает стиль и тайлы OpenFreeMap при открытии.

Правила оформления и использования логотипа — в [DESIGN.md](DESIGN.md).
Границы текущей реализации — в [PRODUCT.md](PRODUCT.md).

## Бэкенд

Spring Boot API находится в `backend/`. Требуется Java 17 или новее.

```bash
cd backend
./mvnw test
./mvnw spring-boot:run
```

По умолчанию API слушает `127.0.0.1:8080`, данные сохраняются в H2
(`backend/data/` при запуске из `backend/`). Настройки: `DB_URL`, `DB_USER`,
`DB_PASSWORD`, `PORT`, `SERVER_ADDRESS`, `SEED_DEMO`, `ADMIN_API_KEY`.

Текущий фронтенд использует моковые данные и ещё не подключён к этому API.
Авторизация, покупка, бронирование и отправка партнёрских заявок через интерфейс
недоступны.

### Защита API

Бронирование, чтение брони и отправка партнёрской заявки требуют `Authorization: Bearer <JWT>`. Укажите
`CUSTOMER_JWT_ISSUER` (HTTPS URL доверенного OIDC-провайдера) и
`CUSTOMER_JWT_AUDIENCE` (audience DamTap). Проверяются подпись, issuer, audience,
срок действия и subject. Без настройки эти операции возвращают 503;
неподтверждённый клиент не может списывать остатки. Провайдер должен выдавать
идентичность после реальной проверки пользователя. Регистрация и выдача токенов
не реализуются этим API. HTTPS должен завершаться на доверенном ingress.

Один покупатель может забронировать суммарно не более трёх порций одного
предложения. Проверка квоты и списание остатков выполняются под одной блокировкой
строки БД. Бронь читается только владельцем; прежние анонимные записи без владельца
через публичное API больше не выдаются. Цены по-прежнему рассчитывает сервер.

Партнёрская заявка требует JWT с `email_verified=true` и совпадением `email`
токена с адресом заявки. Один подтверждённый аккаунт может создать одну заявку;
повторная отправка возвращает исходный receipt. Уникальный `email_key` защищает новые записи от конкурентного дублирования;
при конфликте возвращается 409 с возможностью повторить запрос. Добавленные колонки
nullable для совместимости с прежней БД (включая уникальный applicant_id): существующие записи не удаляются и не
переписываются. Старые заявки остаются у администратора; новый запрос на занятый email получает 409.
Email подтверждается провайдером; право представлять заведение нужно отдельно
проверить до одобрения заявки.

JSON ограничен 16 КиБ до десериализации, включая chunked-тела; превышение даёт
413. Admin-ключ проверяется до чтения тела. По умолчанию публичные записи ограничены
30 запросами в минуту на сетевого peer и 300 суммарно на процесс; превышение даёт
429 и Retry-After. Для административного API — 120 попыток в минуту на peer.
Параметры: `app.public-write-limit-per-minute`,
`app.global-write-limit-per-minute` (положительные целые).

Limiter локален одному экземпляру приложения. При нескольких экземплярах нужен
общий limiter на ingress/в общем хранилище. X-Forwarded-For и Forwarded не доверяются:
за Next.js peer будет адресом proxy, и лимит разделят его клиенты. Для публичного
развёртывания настройте клиентские квоты на доверенном ingress, сохранив серверные
пределы; не включайте доверие к произвольным заголовкам клиента. Ограничения частоты
не заменяют проверку покупателя и защиту OIDC-провайдера от массового создания аккаунтов.
